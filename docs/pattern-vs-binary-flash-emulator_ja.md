<a id="1-what-is-being-compared"></a>
## 1. 何を比較しているか

このエミュレーターは、40記号のアルファベットから1つの記号を分類する、三つのアプローチを比較します。

| 方式 | 説明 |
|---|---|
| **二進の逐次探索** | 40記号を6ビットの整数として表す。候補を1つずつ走査し、候補ごとに6ビットを比較する。平均的なケース：20回の反復。 |
| **二進のインデックス参照** | 最適化したデジタルのベースライン：6ビットの符号をアドレスとする、O(1)のテーブル参照。メモリ読み出し1回＋検証の比較1回。 |
| **光学SCD／RGB・白** | 各記号を、色の層マーカー（R／G／B／白）と、5位置のそろばん符号化十進（SCD）のビード・パターンで表す。4つの層 × 10個のSCDの数字 ＝ 40記号。9つのチャネルすべて（マーカー4＋ビード5）を、1回の並列スナップショットで同時に読み取る。 |

二進のインデックス参照は、不公平な比較を防ぐために、特に含めています。逐次探索は、最悪の場合の二進の走査を反映するため含めています。これは、「パターン対逐次」の議論で、暗黙の藁人形になりがちなものです。

<a id="2-what-flash-pattern-processing-means"></a>
## 2. フラッシュ・パターン処理とは

「フラッシュ・パターン処理」は、二つの源に由来します。

**フラッシュ暗算：**熟練したそろばんの実践者は、1つの数あたりほんの一瞬しか表示されない、多くの数の和を計算できます。研究は、彼らが仮想のそろばんを心の中でシミュレートして、これを行うことを示唆しています。個々の数字の記号ではなく、空間的なビードのパターンに対して操作するのです。この認知的な操作は、数字を1桁ずつ逐次計算するのではなく、パターン全体の変換です。

**構造的な並列復号：**光学ビードのモデルでは、フラッシュ認識に対応するのは、記号のパターン全体 — 色のマーカーと5つのSCDビード位置のすべて — が、1回のCMOS読み出しのステップで取り込まれることです。候補のリストは走査されません。復号の経路は次のとおりです。

```
Step 1 (parallel readout): read all 9 channels simultaneously
Step 2 (threshold pass):   compare all readings against threshold in one vectorized pass
Step 3 (validity check):   verify SCD thermometer code and decode digit
```

総遅延は、アルファベットの大きさにかかわらず、論理的に3ステップです。対照的に、二進の逐次探索の遅延は、アルファベットの大きさに比例して増えます。

これは復号の経路についての構造的な議論であり、ハードウェアの速度についての主張ではありません。

<a id="3-why-this-is-not-real-measured-hardware-power"></a>
## 3. なぜ、これは実測のハードウェア電力ではないのか

このエミュレーターのすべてのエネルギーの値は、設定可能な仮定のもとでの**相対的な単位**です。ワットでも、ジュールでも、測定された物理量でもありません。

エネルギーモデルは、異なる演算に、任意の相対的なコストを割り当てます。

```
binary_bit_compare_energy  = 1.0   (per bit comparison)
binary_memory_read_energy  = 2.0   (per word memory read)
binary_control_step_energy = 0.5   (per loop/branch step)
led_on_energy              = 1.5   (per active LED bead)
cmos_pixel_read_energy     = 0.8   (per CMOS channel read)
optical_threshold_energy   = 0.4   (per threshold comparison)
validity_check_energy      = 0.5   (per SCD validity check)
```

これらの比率は、もっともらしい工学的な直感ですが、いかなる物理デバイスの測定からも導かれていません。これらの値のどれかを変えれば、結果も変わります。エミュレーターの感度分析の節は、これを明示的に示します。

量子優位性は、主張も示唆もされていません。光学ビードコンピューティングの二進コンピュータに対する優位性も、保証されません。このエミュレーターは、このアーキテクチャを技術的に具体化できるか、そして優位になるためにどのような仮定が成り立つ必要があるかを探るための道具です。

<a id="4-what-assumptions-favor-the-optical-bead-model"></a>
## 4. 光学ビードのモデルに有利な仮定

光学パターン処理は、次の場合に、二進の逐次探索よりも低い相対エネルギーと遅延を示します。

1. **LEDの発光コストが低い**（二進のビット比較とメモリ読み出しのコストに対して）。各アクティブなLEDビードのコストが、二進のメモリ読み出し1回より小さければ、光学側が有利になる。

2. **CMOS画素の読み出しコストが低い。**光学的な復号には、9つのCMOSチャネルの読み出し（マーカー4＋ビード5）が必要。各読み出しが二進のメモリ読み出しに比べて安ければ、並列の読み出しは効率的になる。

3. **課題が、大きなアルファベットに対する分類である。**二進の逐次探索の遅延は、O(N)（Nはアルファベットの大きさ）でスケールする。光学の遅延は、3ステップで一定。N = 40では、二進の逐次探索は約140ステップを要するのに対し、光学は3ステップで、Nとともに拡大する構造上の遅延の優位性がある。

4. **センサーノイズが中程度である**（既定のしきい値でσが約0.10未満）。ノイズが低いとき、SCDの温度計符号は、組み込みの誤り検出の仕組みを提供する。無効なビード・パターンは、誤った記号が返される前に検出される。

5. **アルファベットが、符号化空間に対して密である。**4 × 10 = 40通りの可能な組み合わせから40記号を使うため、利用率は100%。二進の6ビット符号化は64状態をカバーするが、使われるのは40のみ。

<a id="5-what-assumptions-favor-the-binary-model"></a>
## 5. 二進のモデルに有利な仮定

二進のインデックス参照が光学モデルを上回るのは、次の場合です。

1. **光学のオーバーヘッドが高い。**LEDの発光とCMOSの読み出しのコストが、二進のビット比較とメモリ読み出しのコストに比べて大きければ、並列の光学読み出しは、1回のインデックス付きメモリ参照より、記号あたり多くの相対エネルギーを消費する。

2. **CMOS画素の読み出しコストが特に高い。**エミュレーターは、記号あたり9チャネルを読み取る。各チャネルの読み出しが約0.8相対単位を超えると、光学のエネルギー予算は急速に増える。

3. **センサーノイズが高い**（既定のしきい値でσが0.10〜0.15以上）。ノイズが高いと、光学の誤り率が上がり、正しい認識あたりの実効コストが増える（誤りには再送あるいは訂正が必要なため）。

4. **アルファベットが小さい。**非常に小さなアルファベット（N ≤ 4）では、逐次的な二進探索でも、わずかな反復で済む。逐次走査に対する光学の並列読み出しの優位性は小さい。

5. **ハードウェアの並列性が使えない。**光学モデルの遅延の優位性は、1回のハードウェアのステップでの、複数チャネルの同時読み出しに依存する。CMOSセンサーを逐次に読まなければならないなら、遅延はチャネル数に比例して増える。

エミュレーターの感度分析の節には、「利益のないケース」のシナリオが含まれ、二進のインデックス参照が、エネルギーと誤り率の両方で勝つパラメータ領域を明示的に示します。

<a id="6-how-to-run-the-emulator"></a>
## 6. エミュレーターの実行方法

**必要環境：**Python 3.8以上。必須の外部依存関係はありません。  
**任意：**PNGのプロット用に`matplotlib`。

```
# Basic run with default parameters (10,000 trials)
python simulator/pattern_vs_binary_flash_emulator.py

# Custom trial count and noise level
python simulator/pattern_vs_binary_flash_emulator.py --trials 5000 --sigma 0.05

# Skip plots even if matplotlib is installed
python simulator/pattern_vs_binary_flash_emulator.py --no-plots

# Help
python simulator/pattern_vs_binary_flash_emulator.py --help
```

**出力ファイル：**

| ファイル | 内容 |
|---|---|
| コンソール | ASCIIの要約表：演算回数、エネルギー、遅延、誤り率、感度分析 |
| `simulator/results/pattern_vs_binary_flash_emulator.csv` | すべての集計指標＋感度分析の行 |
| `simulator/results/pattern_vs_binary_energy.png` | エネルギーの棒グラフ（matplotlibがある場合） |
| `simulator/results/pattern_vs_binary_latency.png` | 遅延の棒グラフ（matplotlibがある場合） |
| `simulator/results/pattern_vs_binary_error_rates.png` | 感度分析のグラフ（matplotlibがある場合） |

**モデルのパラメータの変更：**

すべてのエネルギーのパラメータ、ノイズのパラメータ、二進逐次探索の割合は、`simulator/pattern_vs_binary_flash_emulator.py`の冒頭に、モジュールレベルの定数として定義されています。異なる仮定を探るには、直接編集してください。

```python
# Binary energy model
BINARY_BIT_COMPARE_ENERGY  = 1.0
BINARY_MEMORY_READ_ENERGY  = 2.0
BINARY_CONTROL_STEP_ENERGY = 0.5

# Optical energy model
LED_ON_ENERGY              = 1.5
CMOS_PIXEL_READ_ENERGY     = 0.8
OPTICAL_THRESHOLD_ENERGY   = 0.4
VALIDITY_CHECK_ENERGY      = 0.5

# Noise model
SIGMA_SENSOR               = 0.08
RGB_CROSSTALK              = 0.05
```

<a id="7-how-to-interpret-results"></a>
## 7. 結果の解釈の仕方

### 演算回数の表

各種類の演算の、記号あたりの平均回数を示します。

- 二進の逐次探索は、`bit_comparisons`、`memory_reads`、`control_steps`を報告する。
- 光学SCDは、`active_beads`、`cmos_reads`、`threshold_comparisons`、`validity_checks`を報告する。

これらの回数はモデルによって固定されており（ノイズなし）、平均は、20回の反復の平均的なケースの逐次探索に対する、決定論的な回数に等しくなります。

### エネルギーと遅延の表

- **エネルギー（相対単位）：**すべての演算回数 × それぞれの単位コストの合計を、試行にわたって平均したもの。
- **遅延（ステップ）：**復号の経路における論理ステップ。二進の逐次探索 ＝ `n_iterations × (bits + 1)`。二進のインデックス参照 ＝ 2。光学 ＝ 3。

百分率の比較は、光学が各二進のベースラインとどう異なるかを示します。`vs Bin-Sequential`の百分率が正であれば、光学のほうが相対エネルギーが小さいことを意味します。

### 誤り率の表

このエミュレーターでは、光学モデルだけがノイズによる誤りを受けます。二進のモデルは、誤りがないものとして扱われます（完全なメモリと比較器）。

- **検出された誤り：**SCDの温度計符号が破られている — ビード・パターンが不正。デコーダは認識の失敗を知る。
- **沈黙の誤り：**ビード・パターンは有効なSCD符号だが、誤った記号に対応する。捕まえるには、最近傍の訂正、あるいは冗長符号化が必要。
- **任意の誤り：**総誤り率。

### 感度分析の表

光学のエネルギーのパラメータとノイズ水準が異なる、五つのシナリオ。各行は次を示します。

- そのシナリオでの光学のエネルギー
- 二進のインデックス参照のエネルギー（一定の基準）
- `vs Idx`の百分率：正であれば、エネルギーで光学が勝つ
- そのシナリオのノイズ水準での誤り率
- どちらのアプローチが有利か

この表を読むことで、どの仮定が重要であるかがわかります。「利益のないケース」の行は、悲観的なコストの仮定のもとで、光学が負けることを明示的に示します。

<a id="8-why-this-is-falsifiable"></a>
## 8. なぜ、これは反証可能なのか

このモデルは、述べた仮定のもとで、具体的で検証可能な予測を行います。

1. **エネルギーの反証可能性：**演算あたりの、実際のLEDの発光、CMOSの読み出し、アナログのしきい値比較のコストを測定し、実際のデジタルのメモリ読み出しとビット比較のコストと比較できれば、相対エネルギーの比率は測定可能になる。実際の比率が「利益のない」範囲にあるなら、光学処理は負ける。

2. **遅延の反証可能性：**3ステップの光学の遅延は、完全に並列なCMOSの読み出しを仮定している。ハードウェアが逐次のチャネル読み出しを強いるなら、遅延は`O(channels)`でスケールする。CMOSの読み出しタイミングを測定する実験が、並列ステップの仮定を確認あるいは反証する。

3. **誤り率の反証可能性：**光学の誤りモデルは、具体的な誤り率とノイズの関係（σ → 誤り率の曲線）を予測する。これらは、ソフトウェアで異なるσの値を使って、あるいはハードウェアで較正されたノイズの注入によって、試験できる。

4. **アルファベットのスケーリングの反証可能性：**このモデルは、逐次的な二進に対する光学の遅延の優位性が、アルファベットの大きさとともに増えると予測する。これは、`ALPHABET_SIZE`を変えることで、ソフトウェアで直接試験できる。

これらの予測のどれも、光学ビードのモデルが「正しい」ことを要求しません。二進処理より良くなる、あるいは悪くなる条件を定めるものです。

<a id="9-limitations"></a>
## 9. 限界

| 限界 | 詳細 |
|---|---|
| **ハードウェアの測定なし** | すべてのエネルギーの値は、相対的なモデルの単位であり、実際の電力の測定ではない。 |
| **簡略化した二進モデル** | 現実の二進プロセッサは、パイプライン処理、キャッシュ、分岐予測を用いる。逐次モデルは単純で、インデックスモデルは楽観的。どちらも正確なCPUのマイクロアーキテクチャのモデルではない。 |
| **簡略化した光学モデル** | 現実の光センサーには、暗電流、ショットノイズ、非線形性、空間的なばらつき、温度依存性があり、加法的なガウスノイズでは完全にはとらえられない。 |
| **クロストークのモデル** | RGBのクロストークは、固定の割合としてモデル化されている。波長チャネル間の現実のスペクトルの重なりは、波長に依存し、フィルターの品質に依存する。 |
| **遅延のモデル** | 論理ステップ（読み出し／しきい値／妥当性）は、現実のクロックサイクルと等価ではない。現実のハードウェアでは、論理ステップごとに多くのクロックサイクルが必要か、複数のステップがパイプライン化されるかもしれない。 |
| **誤りモデルの範囲** | 検出された誤り率は、SCDの温度計の妥当性に依存する。層の混同による沈黙の誤りもモデル化されている。OAMや偏光の自由度による誤りは含まれない（このモデルは色＋SCDのビードのみを用いる）。 |
| **アルファベットの構造** | 40記号のアルファベットは、4層 × 10桁のみを用いる。より大きなアルファベットへの拡張には、追加の自由度あるいはより多くの層が必要で、それぞれが新たなノイズ結合の項をもたらす。 |
| **ハードウェアの試作機なし** | 2026-06-06時点で、物理的な光学ビードのハードウェアは存在しない。すべての結果は、ソフトウェア・シミュレーションによる。 |
| **エネルギーモデルの比率は仮定** | `LED_ON_ENERGY < BINARY_MEMORY_READ_ENERGY`という主張は、測定ではなく、モデルの仮定である。異なる現実のハードウェアの選択では、異なる比率が得られる。 |
