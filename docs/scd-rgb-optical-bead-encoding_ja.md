# SCDとRGB光学ビードの符号化

[English Version](scd-rgb-optical-bead-encoding.md)

## そろばんに着想を得た多値パターン計算のための、慎重なフレームワーク

> **ステータス：**概念的フレームワーク／シミュレーションの目標  
> **範囲：**SCD、LED-CMOS、RGB／白の光学ビードの符号化  
> **重要：**この文書は、限定的で検証可能な主張のみを行います。既存のコンピューティングシステムに対する普遍的な優位性は主張しません。

---

## 1. 目的

この文書は、電子的・光学的な試作機のための、そろばんに着想を得た十進パターン符号化システムの、慎重で検証可能な版を定義します。

目標は、再現可能な実験の目標を定めることです。

1. **そろばん符号化十進（SCD）**を用いて、十進の数字を符号化する、
2. SCDのビード・パターンを、LED／CMOSで読み取れる光パターンに対応づける、
3. 一つのSCDセルを、RGB／白のアクティブな光学層で拡張する、
4. どの誤りが検出可能で、どれが沈黙し、どれが追加の冗長性を必要とするかを評価する。

このフレームワークは、広範な性能の主張ではなく、限定的で反証可能な主張を行うべきです。

---

## 2. SCD：そろばん符号化十進

そろばんの一本の軸は、次を用いて一つの十進の桁を表します。

- 5を表す上の1つの珠、
- それぞれ1を表す下の4つの珠。

したがって、簡単な電子的SCDセルは、5ビットで表せます。

```text
[H, L4, L3, L2, L1]
```

ここで：

- `H`は、上の珠、
- `L4..L1`は、下の珠、
- 下の珠は、温度計式の符号を用います。

考えられる符号化の一つは、次のとおりです。

| 数字 | SCDパターン |
|---:|---|
| 0 | `00000` |
| 1 | `00001` |
| 2 | `00011` |
| 3 | `00111` |
| 4 | `01111` |
| 5 | `10000` |
| 6 | `10001` |
| 7 | `10011` |
| 8 | `10111` |
| 9 | `11111` |

32通りの5ビットパターンのうち、有効なのは10通りだけです。残りの22通りは、構造上、無効です。

これにより、SCDは有用な性質を持ちます。多くのランダムなビット誤りが無効なパターンになり、検出できるのです。

しかし、検出は完全ではありません。一部のビット反転は、有効なSCDの数字を、別の有効なSCDの数字に変えます。追加の検査がない限り、これらは**沈黙の誤り**です。

## 3. SCDが主張できること、できないこと

### 安全な主張

SCDは、5ビットの全空間の内側に、より小さな有効な状態空間を定義します。これにより、ランダムなビット反転が、検出可能な無効状態になる可能性が高まります。

### 安全でない主張

SCDを、追加の冗長性なしに、完全な誤り検出であると述べるべきではありません。

10通りのSCDの数字にわたる、単一ビットの反転について：

- 50通りの単一ビット反転の事象が存在する：10通りの数字 × 5つのビット位置。
- 24通りは構造上無効になり、検出される。
- 26通りは別の有効な数字になり、沈黙の誤りになる。

したがって、この特定の単一ビット反転のモデルのもとでは：

```text
single-bit detected fraction ~= 48%
single-bit silent-error fraction ~= 52%
```

これでも有用ですが、完全ではありません。

誤り訂正には、追加の冗長性、繰り返しのサンプリング、パリティ、距離の拡張、較正の信頼度、あるいはより高水準の検証が必要です。

## 4. LED-CMOSの対応

近い将来の試作機は、SCDパターンを小さなLEDアレイに対応づけ、CMOSセンサーで読み取ることができます。

```text
SCD bits -> LED bead pattern -> CMOS image -> decoder -> digit
```

これは、古典的な光学・電子のパターン認識の試作機です。

近い将来に使えるハードウェア：

- RGB LEDマトリクスまたはマイクロLEDディスプレイ、
- CMOSイメージセンサーまたはカラーカメラ、
- 光学的な分離／筐体、
- しきい値あるいは最近傍のデコーダ、
- 色と強度のドリフトのための、較正フレーム。

この試作機は、ある種のワークロードのもとで、空間的なビード状のパターンが、通常の二進符号化よりも、復号、可視化、検証しやすいかどうかを試験できます。

## 5. RGB／白の光学ビードの拡張

慎重な光学的拡張として、アクティブな色の層を用います。

```text
R, G, B, White
```

ここで：

- `R` ＝ 赤の発光、
- `G` ＝ 緑の発光、
- `B` ＝ 青の発光、
- `White` ＝ 赤・緑・青の同時発光。

4つのアクティブな光学層と、10通りのSCDの数字パターンを組み合わせると、次が得られます。

```text
4 layers × 10 digit patterns = 40 symbols
```

これは、実証された40進のコンピュータというよりも、**40記号のアルファベット**と呼ぶほうが適切です。

より安全な用語は、次のとおりです。

```text
40-state RGB/white SCD optical bead cell
```

## 6. 既定のモデルで黒／消灯を除外する理由

以前の拡張では、次を検討しました。

```text
Black/off, R, G, B, White
```

これは、次を与えるはずでした。

```text
5 layers × 10 digit patterns = 50 symbols
```

しかし、黒／消灯は、光がないことを表すため、情報を担うアクティブな層としては、物理的に弱くなります。次のものに、より影響されやすくなります。

- 環境光、
- 暗電流のオフセット、
- センサーのバイアス、
- 隣接するLEDの漏れ光、
- しきい値の曖昧さ、
- 意図した無発光のマーカーと、欠落した、あるいは故障した信号とを区別できないこと。

したがって、既定の試作機は、まずアクティブな光学層のみを用いるべきです。

```text
R / G / B / White
```

これにより、数は少ないものの、より頑健な40状態のモデルが得られます。

## 7. 重要な問題：数字のゼロと層の識別

重要な設計上の問題があります。

SCDの数字`0`は、次のように表されます。

```text
00000
```

層を、アクティブな珠を色づけることだけで符号化する場合、数字のゼロには、点灯する珠がありません。その場合、検出器は、記号が次のどれだったかを知ることができません。

```text
R-zero, G-zero, B-zero, or White-zero
```

すべてが空白に見えるからです。

したがって、実用的なRGB／白のSCD光学ビードのセルには、**層マーカー**あるいは**参照ピクセル**が必要です。

最小の記号は、次のように表せます。

```text
[layer marker] + [5 SCD bead positions]
```

層マーカーは、数字パターンがゼロであっても、選ばれた色の層で常に点灯します。

これにより、物理設計は、純粋な5位置のセルから、**5+1位置のセル**へと変わります。

```text
M | H L4 L3 L2 L1
```

ここで、`M`は光学的な層マーカーです。

このマーカーは、復号可能性を高め、40状態のアルファベットを明確に定義します。

## 8. デコーダの原理

簡単なデコーダは、最近傍の照合を用いることができます。

1. マーカーと5つのビード位置を、RGB強度のベクトルとして取り込む。
2. マーカーから層を判定する。
3. 各ビード位置を、期待される層の色に対して読み取る。
4. アクティブ／非アクティブのビード位置を、5ビットのSCDパターンに変換する。
5. SCDパターンを復号する。
6. 無効なSCDパターンをリジェクトする。
7. 信頼度の低い色あるいは強度の測定をリジェクトする。

これにより、三つの結果がありえます。

| 結果 | 意味 |
|---|---|
| 正しい | 復号された層と数字が、送信された記号と一致する |
| 検出された誤り | 無効なSCDパターン、無効な層、または低い信頼度 |
| 沈黙の誤り | 別の有効な層／数字として復号された |

鍵となる指標は、全体の誤り率だけでなく、検出された誤りと沈黙の誤りの比率です。

---

## 9. 安全で反証可能な主張

現時点での安全な主張は、次のとおりです。

1. SCDは、32通りの5ビットパターンのうち、10通りの有効な状態だけを使う。
2. SCDは、別個のパリティビットなしに、一部の無効なパターンを構造上検出できる。
3. SCDは、すべてのビット誤りを検出するわけではない。
4. RGB／白のアクティブな層は、SCDと組み合わせると、40記号のアルファベットを定義できる。
5. 実用的な40状態のセルには、数字のゼロの層を識別するための、マーカー／参照位置が必要である。
6. LED-CMOSの試作機は、低コストの古典的なハードウェアで、この考えを試験できる。
7. 実際の性能は、ノイズ、クロストーク、ドリフト、較正の誤差、光学的なアライメントの誤差のもとで、測定しなければならない。

---

## 10. 測定されるまで避けるべき主張

実験的な証拠が得られるまでは、次の主張を避けてください。

- 完全な誤り検出、
- 保証された誤りのないコンピューティング、
- すべてのワークロードにおける、既存のコンピューティングシステムの代替、
- ベンチマークなしでの大幅なエネルギー削減、
- 製品化の準備が整っていること。

適切な公開時の表現は、次のとおりです。

> これは、そろばんに着想を得た多値のパターン符号化フレームワークであり、低コストのLED-CMOSの試作機で試験できる可能性がある。

## 12. 結論

中核となる考えは、依然として価値があります。そろばんに着想を得た空間パターンは、多値で、視覚的に復号でき、パターン指向の計算を探る、有用な方法をもたらすかもしれません。

最も信頼できる道筋は、普遍的な優位性を主張することではなく、小さな反証可能な試作機をつくることです。

```text
SCD -> RGB/white LED pattern -> CMOS capture -> decoder -> error statistics
```

試作機が、現実的なノイズのもとで、頑健な検出、低い沈黙の誤り率、有用なパターン認識の挙動を示せば、フレームワークはより強くなります。

そうでなければ、モデルを改訂すればよいのです。
